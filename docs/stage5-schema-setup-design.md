# Stage 5: configuration schema, `pyclm check`, one command line, pattern preview — design

Date: 2026-09-08. Status: **implemented** the same day on `core-refactor`,
with the five decisions in §9 taken as recommended. Code: `pyclm/schema.py`,
`pyclm/check.py`, `pyclm/mmconfig.py`, `pyclm/cli.py`, `pyclm/preview.py`,
`pyclm/templates.py`; the TOML reference in the user docs is generated by
`documentation/ext/schema_tables.py`. Tests: `tests/test_schema.py`,
`tests/test_check.py`, `tests/test_cli.py`, `tests/test_preview.py`. Interactive setup (forms, a positions
editor, run control in the GUI) is Stage 5b and waits until this has been
used by a real person.

Stage 5 is seam **F** of [assessment-2026-09.md](assessment-2026-09.md)
(configuration has no schema) and the first half of §4.5 (setup and
interactivity). Everything before it improved what happens once a run
starts; this stage is about the hour before: writing the files, finding out
they are wrong, seeing what a method will do, and starting the run with one
command.

---

## 1. What exists today (verified on `f04d1d6`)

- `directories.experiment_from_toml` parses the experiment TOML by hand
  with `.get` defaults. A missing required key is a `KeyError` at start-up;
  an unknown key in `[pattern]`, `[segmentation]` or `[tracking]` is passed
  to the method as a keyword argument, where every built-in swallows it in
  `**kwargs`, so a misspelled `bar_sped` silently leaves the default in
  place. Unknown keys elsewhere are ignored.
- Per-channel `config_groups` / `device_properties` overrides
  (`[channels.638.config_groups]`) are documented but never applied: the
  parser looks for a `config_groups` key *inside* the override table
  (`directories.py`, "get channel-specific config groups"), so the tables
  are always empty. Fixed here (§8).
- `read_schedule` defaults `steps` to 10 and `interval_seconds` to 10 when
  missing, silently.
- `run_pyclm` reads `pyclm_config.toml` with `config["config_path"]`
  (`KeyError` if absent) and `.get` for the rest.
- Three entry points: `pyclm` (run), `convert_hdf5s`, `gui`; a new user has
  to know which script does what.
- The docs zoo (`documentation/ext/zoo_gallery.py`) already renders any
  pattern method on a sample image through `ZooContext` and
  `make_zoo_subclass`; nothing renders a method with a *real* TOML on a
  *real* image.
- `pydantic` 2.13 is installed (a dependency of useq-schema): no new
  dependency for the schema.

## 2. The schema (`pyclm/schema.py`)

Pydantic v2 models, `extra="forbid"` everywhere except the three method
tables (`[segmentation]`, `[tracking]`, `[pattern]`), whose extra keys are
the method's keyword arguments and are checked against the method's
signature by `pyclm check` (§4). Every model carries a `format_version`
(current: 1; a file without one is treated as current; a newer one is an
error). The models validate and then build the same `Experiment` /
`ExperimentSchedule` objects as before, so nothing downstream changes.

### 2.1 Experiment TOML (`ExperimentConfig`)

| Key | Type | Default | Notes |
|---|---|---|---|
| `format_version` | int | 1 | must be ≤ the current version |
| `[config_groups]` | table `group = "preset"` | `{}` | applied to every acquisition of the experiment |
| `[device_properties]` | table `"Device-Property" = value` | `{}` | key must contain exactly one `-`; value bool / int / float / str |
| `[imaging]` | table | all defaults | defaults for the imaging channels |
| `imaging.exposure` | float > 0 | 10 | ms |
| `imaging.every_t` | int ≥ 1 | 1 | counted from `t_delay` |
| `imaging.save` | bool | true | |
| `imaging.binning` | int ≥ 1 | 1 | the same for every channel |
| `imaging.config_groups`, `imaging.device_properties` | tables | `{}` | applied to imaging channels only |
| `[channels]` | table | required | |
| `channels.group` | str | required | the MicroManager group that switches channels |
| `channels.presets` | list[str], ≥ 1, unique | required | acquisition order |
| `[channels.<preset>]` | table | none | `<preset>` must be in `presets`; keys `exposure`, `every_t`, `config_groups`, `device_properties`; `binning` is refused with a message |
| `[stimulation]` | table | required | |
| `stimulation.exposure` | float ≥ 0 | required | 0 means no stimulation |
| `stimulation.every_t` | int ≥ 1 | 1 | |
| `stimulation.save` | bool | true | the camera frame taken during stimulation |
| `stimulation.binning` | int ≥ 1 | imaging binning | |
| `stimulation.config_groups`, `stimulation.device_properties` | tables | `{}` | |
| `[segmentation]` | method table | none | `method` (str), `save` (bool, `save_output` accepted), other keys → kwargs |
| `[segmentation.<name>]` | method table | none | a named segmentation of the same frames |
| `[tracking]` | method table | none | `method`, `save`, `segmentation` (name of the table to track, default `"segmentation"`), other keys → kwargs |
| `[pattern]` | method table | required | `method`, `every_t` (int ≥ 1, default 1), other keys → kwargs |
| `t_delay` | int ≥ 0 | 0 | timepoints |
| `t_stop` | int ≥ 0 | 0 | own timepoints; 0 = run to the end |

Cross-field rules: `[tracking].segmentation` must name `[segmentation]` or
a `[segmentation.<name>]` table that exists; `presets` are unique; every
`[channels.<x>]` names a preset.

### 2.2 `schedule.toml` (`ScheduleConfig`)

| Key | Type | Default |
|---|---|---|
| `format_version` | int | 1 |
| `[timing].steps` | int ≥ 1 | required |
| `[timing].interval_seconds` | float > 0 | required |
| `[timing].setup_time_seconds` | float ≥ 0 | 2.0 |
| `[timing].time_between_positions` | float ≥ 0 | 2.0 |

`steps` and `interval_seconds` were defaulted silently before; a run of 10
timepoints at 10 s because a key was misspelled is exactly the mistake the
schema exists to catch.

### 2.3 `pyclm_config.toml` (`PyclmConfig`)

| Key | Type | Default |
|---|---|---|
| `format_version` | int | 1 |
| `config_path` | str | required (the MicroManager `.cfg`) |
| `affine_transform` | 2 × 3 list of floats | required |
| `slm_shape_h`, `slm_shape_w` | int > 0 | required |
| `focus_device` | str | `"ZDrive"` |
| `settle_time_seconds` | float ≥ 0 | 1.0 |
| `[output].format` | `"ome-zarr"` \| `"hdf5"` | `"ome-zarr"` |
| `[output].pattern_policy` | `"on_change"` \| `"all"` \| `"none"` | `"on_change"` |
| `[output].export_imagej` | bool | true |

### 2.4 Error messages

Pydantic's errors are rewritten into one line each, in the vocabulary of
the file: `bar10.toml: [imaging] exposure must be greater than 0 (got
-5)`; `bar10.toml: unknown key 'exposur' in [imaging] (did you mean
'exposure'? allowed: binning, config_groups, device_properties, every_t,
exposure, save)`; `bar10.toml: [channels.638] names a preset that is not
in presets ['545']`. All problems in a file are reported together
(`ConfigError.problems`), not one at a time.

## 3. Where the schema is used

`directories.experiment_from_toml`, `read_schedule` and `run_pyclm`'s
config reading go through the models; their signatures do not change and
they raise `ConfigError` instead of `KeyError`. The experiment-TOML
reference in the user docs is generated from the models at docs build time
(a small Sphinx directive, `documentation/ext/schema_tables.py`), so the
reference cannot drift from the code.

---

## 4. `pyclm check <dir>` (`pyclm/check.py`)

Reads a directory and reports findings (error / warning / info) with the
file and the key each one concerns, without touching hardware:

1. `pyclm_config.toml` (directory, then `--config`, then the working
   directory): valid; `config_path` exists (warning only, it may live on
   another machine).
2. `schedule.toml`: valid.
3. Every other `*.toml`: valid experiment file (all problems listed).
4. Positions: `PositionList.pos` or `multipoints.xml` present (a dry run
   may instead use `dry_run.yml` or TIF names); every label's stem has a
   TOML (error); every TOML is used by at least one position (warning);
   duplicate labels (error).
5. Methods: pattern, segmentation and tracking method names are registered
   (built-ins plus any passed in); their keyword arguments match the
   method's `__init__` signature (unknown → error with a did-you-mean;
   missing without default → error).
6. Requirements: the pattern method is constructed and asked what it needs;
   a channel it names must exist; a named segmentation it names must be
   configured; `tracks` needs `[tracking]`; `seg` needs `[segmentation]`;
   `[tracking].segmentation` must exist. A configured but unused
   `[segmentation]` / `[tracking]` is a warning.
7. MicroManager configuration: if the `.cfg` at `config_path` (or
   `--mm-config`) is readable it is parsed as text; every config group and
   preset the TOMLs use must exist (error); every device in a
   `device_properties` key must exist (error); a property not listed in the
   file is a warning (it may still exist on the device). Otherwise an info
   line says presets were not checked.
8. Timing: the plan is built and `over_budget(settle_time_seconds)` is
   reported per timepoint (warning), plus a summary of frames per
   experiment.
9. Existing outputs for the experiments (error: move or delete).
10. `--dry`: copies the directory to a temporary place, sets two timepoints,
    and runs it on the virtual microscope; a failure is reported as an
    error with the exception.

`pyclm run` calls the same check first and refuses to start when there are
errors (`--force` overrides, `--no-check` skips); warnings are printed and
the run proceeds.

## 5. One command line (`pyclm/cli.py`)

```
pyclm run <dir> [--config] [--dry] [--gui] [--no-check | --force]
pyclm check <dir> [--config] [--mm-config] [--dry]
pyclm preview <dir> <position-or-toml> (--image FILE | --snap) [--config] [--out] [--t N] [--pixel-size-um]
pyclm export <dir> [channels...] [--config]
pyclm gui <dir>
pyclm new <dir> [--template open-loop|closed-loop] [--name NAME]
```

`pyclm <dir> [--dry] [--gui]` (the old form) still works: a first argument
that is an existing directory means `run`. `convert_hdf5s` and `gui` stay
as aliases. Custom methods still need the Python entry point
(`run_pyclm(..., pattern_methods=...)`); `check` and `preview` accept the
same dictionaries from Python.

---

## 6. `pyclm preview` (`pyclm/preview.py`)

Runs the segmentation(s) and the pattern method of one experiment on one
image and writes what a user needs to judge them, into
`<dir>/preview/<label>/`: `raw_<channel>.tif`, `labels_<channel>[_<name>].tif`,
`pattern_camera.tif` (float, camera space), `pattern_overlay.png` (the
raw image with the pattern in cyan), `pattern_dmd.tif` (uint8, DMD space,
through the affine from `pyclm_config.toml`), and `preview.json` (method,
kwargs, requirements, the settings the method asked to change, pixel size,
timings). The image comes from `--image` (a TIF; the first plane of a
stack; used for every channel the method needs) or `--snap` (the real
microscope: the channel's presets, device properties and exposure are
applied and one frame snapped per required channel). The experiment is a
position label from the position list or a TOML stem. The machinery is the
same as the run's: `SegmentationProcess.request_method` / `run_model`,
`PatternProcess.request_method`, a `DataDock` and `PatternContext`,
`SLMBuffer.pattern_to_slm`, so what preview shows is what the run does.

---

## 7. `pyclm new` (`pyclm/templates/`)

Two templates from the lab's current experiments: `open-loop` (a bar
pattern, no segmentation) and `closed-loop` (Cellpose segmentation and a
per-cell pattern). Each writes `schedule.toml`, `<name>.toml`,
`pyclm_config.toml` and a `README.txt` that says what to edit and to run
`pyclm check` next. Nothing is overwritten.

## 8. Behaviour changes

- Unknown keys are errors (they were ignored or swallowed). A TOML with a
  stray key stops at `check` / `run` with a message naming it.
- `steps` and `interval_seconds` are required in `schedule.toml`.
- Per-channel `config_groups` / `device_properties` overrides now apply
  (they never did; known-issues #30).
- `t_delay` / `t_stop` written after `[pattern]`, as the documentation's own
  example showed, were keys of the pattern table and were silently swallowed
  by the method's `**kwargs`; the schema now refuses them there with a
  message saying where they go, and the documented examples put them at the
  top of the file (known-issues #31).
- The signature check treats `channel` as the user's argument for pattern
  methods and as PyCLM's for tracking methods; dispatching bases (`bar`,
  `wave`, whose `__new__` picks a subclass) accept the union of their
  subclasses' arguments.
- `run` refuses to start on check errors unless `--force`.
- `format_version` keys are accepted (and written by `pyclm new`); files
  without one are current.

---

## 9. Decisions (all taken as recommended)

1. Scope: schema, check, CLI and preview now; interactive setup as 5b.
2. Strictness: unknown keys and unknown method arguments are errors;
   missing presets are errors when the `.cfg` is readable, warnings
   otherwise.
3. `pyclm run` runs the check first; errors stop the run unless `--force`.
4. Preview inputs: a TIF or a live snap.
5. Templates: open loop and closed loop, from the lab's experiments.
